# issue1020：连接失败详情与外部文件移动

日期：2026-10-21。对应 [issue1020.md](../issue/issue1020.md)。沿用 Electron、React、TypeScript、Node fetch/fs、Zod、Vitest 和 Playwright；没有新增依赖或改动模型提示词。

## 1. 连接失败详情

### 用户操作

设置页保持原布局，只在连接测试失败的状态文字旁增加“查看详情”按钮。点击后打开一个独立、可滚动、可选择复制文本的窗口。关闭详情即可继续操作原设置页。下一次测试成功后，按钮消失；切换配置时也清除入口。

详情显示：

- 测试配置名、模型、端点、时间、超时设置以及最终错误代码和中文说明。
- 各次请求的 URL、方法、输出格式、脱敏 Headers、开始时间和耗时。
- HTTP 状态和响应 Headers，以及响应正文；JSON 便于阅读地格式化，HTML/普通文本作为原始文本显示。
- 无 HTTP 响应时展示网络异常及底层原因，例如 `ECONNREFUSED`；缺少密钥等请求前失败明确显示“未发出 HTTP 请求”。

对于 issue 中的“模型返回空内容或不支持的消息格式”，现在可以直接查看 `choices`、`message.content`、`finish_reason`、服务端错误和 usage 等实际返回。不会仅凭一句错误摘要推断是模型、额度还是协议问题，也没有为某个模型加入特判。

### 请求与数据流

1. `llm:test` 校验配置，并在主进程解析当前输入或已保存的认证凭据。
2. 为这一次固定连接测试建立独立 Provider，用 `ConnectionDiagnostics.fetcher()` 包装网络调用。写作请求仍使用原有 Provider；不会收集作文内容。
3. 包装器读取响应副本并记录状态，原响应继续交给既有解析和校验链。格式降级、一次修复、有限瞬态重试和 Ollama 清理的响应都属于同一报告。
4. 测试失败后，仅将报告 ID 附加到普通失败结果；报告本体留在主进程内存中。`llm:test-details` 根据 ID 打开独立窗口。
5. 新测试替换旧报告，主窗口关闭时清除报告并关闭详情窗口。已经打开的详情是该次测试的静态快照。

只保留最新报告，不写文件、日志或配置。请求/响应中的认证 Headers、Cookie、常见密钥字段及已知密钥的直接或编码回显会脱敏。单次正文显示上限为 1,000,000 字符，超出时显示截断说明，不伪称完整。

详情窗使用 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`，不加载 preload；CSP 禁止脚本和外部资源。所有服务端数据先转义再放入 `<pre>`，即使响应是 HTML 或包含脚本，也只作为文本展示。

代码入口：[connection-diagnostics.ts](../electron/llm/connection-diagnostics.ts)、[main.ts](../electron/main.ts)、[SettingsDialog.tsx](../src/components/SettingsDialog.tsx)、[preload.ts](../electron/preload.ts)、[schema.ts](../src/models/schema.ts)。

## 2. 文件移动后的保存状态

### 采用的方式

采用“原路径失效后解除关联、标为未保存”的方式，不扫描磁盘猜测移动后的文件位置。

正文仍完整保留在编辑器和自动草稿里；文件名保留用于辨认。再次点击保存会要求选择位置，也可以自行打开移动后的文件。旧路径不会因普通保存而自动重建。

### 根因

原实现只记住 `documentId → path`，没有重新核验文件是否存在。保存时把 `ENOENT` 当作“尚无磁盘内容”，随后将临时文件 rename 到旧地址，因此移动原文件后会悄悄创建第二份文件。

### 实现流程

- `Documents.checkFile(id)` 通过主进程 `stat` 检查关联。明确不存在、路径中的父目录失效或目标不是普通文件时解除关联；权限或临时 I/O 失败不能证明文件移动，因此保留关联并允许自动草稿继续写入。
- renderer 只传文档 ID，不接收或自行操作文件路径。每两秒、主窗口重新获得焦点、准备离开文档时检查；丢失关联后同步更新文档快照，设置 `hasFile=false`、`dirty=true`，显示“未保存至文件”。
- 保存和另存为完成会推进本地关联版本，过期检查结果不能将刚保存成功的文档再次标为丢失。
- 主进程保存独立检查旧路径，并在临时文件写好后、替换目标前再次检查。如果用户在后台检查前立即点击保存，本次写入会先被拒绝并提示重新选址；再次点击保存打开位置选择框。失败时清理临时文件。
- 草稿写入和恢复也核验路径，丢失关联按 `path: null`、未保存状态存入草稿。退出或重启不会恢复虚假的“已保存”。旧草稿即使未包含 `hasFile` 字段，也按真实路径核验。

保留既有的磁盘内容冲突确认、BOM/CRLF、原子写入和保存期间新增输入保护。不修改 Finder 中已移动的文件。该实现没有跨目录追踪文件身份；检查和替换仍是 Node 文件系统操作，不能宣称对任意同一时刻的外部移动具有事务级锁定。

代码入口：[documents.ts](../electron/storage/documents.ts)、[App.tsx](../src/App.tsx)。
