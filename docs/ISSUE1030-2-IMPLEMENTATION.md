# issue1030_2：重启保留模型分析暂停状态

完成日期：2026-10-30。对应 [issue1030_2.md](../issues/issue1030_2.md)，修复版本 1.0.2。

## 问题与最终行为

此前“暂停自动分析”已经把 `autoAnalyze: false` 保存到设置，但“停止并释放模型”只设置 React 内存中的 `modelsStopped`。重新启动后该内存状态恢复为 false，原来的 `autoAnalyze: true` 又触发分析。

现在两种操作都会保存暂停状态。主界面和设置窗口中的停止入口行为一致；下次启动恢复草稿后保持“已暂停”，继续输入也不会自动请求模型。只有点击“恢复自动分析”或在设置中明确开启“自动分析”才恢复自动调度。选区、全文、重新评估等手动操作仍可用。

打开设置时的临时暂停、正常退出时为清理请求而产生的临时暂停，不会改写用户的自动分析偏好。模型卸载失败与暂停状态保存分别处理；卸载失败不撤销已经保存的暂停。磁盘写入失败会提示“下次启动可能恢复自动分析”，当前会话仍保持暂停并继续尝试卸载。

## 技术栈与实现逻辑

沿用 React、TypeScript、Electron IPC、Node 文件 API、Vitest、Playwright，无新增依赖、设置字段或数据迁移。

1. [App.tsx](../src/App.tsx)：停止时立即关闭调度，清理全文请求，把当前设置的 `autoAnalyze` 改为 false。通过现有 `settings:save` IPC 保存后，再完成停止与释放；保存失败也会继续释放。
2. 暂停/恢复按钮及停止按钮共用 `persistAutomatic` 写入入口。`analysisSettingsWrite` 保存当前写入 Promise，正常关闭窗口和 ⌘Q 在退出前等待它，防止“刚点击停止就退出”丢失状态。
3. [SettingsDialog.tsx](../src/components/SettingsDialog.tsx)：点击停止时，只把当前设置草稿的 `autoAnalyze` 改为 false，其余未保存的模型名称、参数、密钥输入保持原样；停止操作不会顺带保存这些草稿。用户之后保存设置时，不会把停止前的 true 再写回。
4. 成功保存设置时清除临时 `modelsStopped` 标记，使用户在设置里主动开启自动分析能立即生效；实际开关由保存后的 `autoAnalyze` 决定。
5. 沿用 [LocalStore](../electron/storage/store.ts) 的设置写入与启动恢复流程。启动完成、读取设置后才配置分析调度，因此恢复草稿不会在读到暂停状态之前发起请求。

本次没有改变模型请求协议、加密方式或安装版/开发版数据隔离方案。
