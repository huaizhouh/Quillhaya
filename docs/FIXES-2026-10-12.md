# 四项问题修复：实现方法与验证记录

> 本文保留此前四项修复的历史记录。后续 `issue1012` 已按用户选择将附近上下文变化改为“保留反馈、提示变化、手动重新评估”；当前规则和新增功能以 [issue1012 实现说明](ISSUE1012-IMPLEMENTATION.md) 为准。

日期：2026-10-12。沿用 Electron + React + TypeScript + CodeMirror + Node fetch + Zod，没有引入新的运行时依赖，也没有修改用户实际的模型配置、凭据或作文。

完整技术栈和整体架构见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。这里集中说明本次改动，方便逐项审阅。

## 1. 添加模型导致界面失效，⌘Q 无法退出

**根因**：`SettingsDialog` 的 Headers 状态使用了普通 `useState(JSON.stringify(...))`。其参数表达式会在每次渲染时执行。添加模型之后，选中 ID 属于尚未保存的 `draft.profiles`，但表达式仍到父组件的已保存 `settings.profiles` 查找；得到 `undefined` 后访问 `.headers` 抛错。ErrorBoundary 捕获异常后卸载 App，连带卸载菜单监听器，主进程却仍等待 renderer 确认退出。

**修复**：

- Headers 改为惰性初始化 `useState(() => ...)`，只在设置窗口挂载时读取当前默认配置；后续切换使用 draft 中的配置。
- 添加达到 25 个配置或正在保存/测试时禁用添加按钮，保持与 Schema 上限一致。
- ErrorBoundary 保留最新文档快照。界面异常时，调用固定 IPC `app:renderer-failed` 保存草稿、取消模型请求，并显示重新载入按钮及可复制的正文。
- 主进程收到界面失败通知后，⌘Q 等待草稿写入完成便退出，不再等待已卸载的 React 菜单监听器。若实际草稿写入失败，显示原生提示，允许返回复制或明确选择退出。
- 操作正常时，原有保存/取消退出流程继续生效。

**代码**：[SettingsDialog.tsx](../src/components/SettingsDialog.tsx)、[main.tsx](../src/main.tsx)、[App.tsx](../src/App.tsx)、[Electron main.ts](../electron/main.ts)、[preload.ts](../electron/preload.ts)。

## 2. 下一句完成后，前一句被反复审议

**根因**：原缓存签名包含后一句完整文本。后一句从未完成变成完整时，即使前一句完全未变，其签名也会改变；已完成结果被作废，在途请求也可能被取消并重新发送。

**修复规则**：

| 变化 | 自动行为 |
| --- | --- |
| 在末尾继续输入、完成下一句、编辑后一句 | 保留此前未变句子的反馈和在途请求 |
| 当前句原文改变 | 取消旧请求，分析新句，拒绝迟到旧响应 |
| 当前句前两句上下文改变 | 重新核验受影响句子 |
| 题目、写作模式、当前模型参数或凭据改变 | 重新分析 |
| 主题、字号、停顿延迟、非当前模型配置改变 | 不作废当前结果，不取消在途分析 |
| 手动选择某句分析 | 允许主动重新审议，使用此时的前后文 |

后一句仍可以随请求发送，但只作为发起请求时的上下文快照，不进入自动失效签名。仍保留文档 ID、请求 UUID、签名、原文和当前位置检查；没有通过关闭版本校验来避免重复分析。

**代码**：[coordinator.ts](../src/core/coordinator.ts)、[App.tsx](../src/App.tsx)、[Electron main.ts](../electron/main.ts)。

## 3. 模型字段、中文说明与类型不符合要求

**根因**：原实现只启用 `json_object`，只能约束 JSON 语法。提示词中的伪示例将枚举写成 `good|needs_revision|...` 一类字符串；校验失败后的修复指令没有具体字段错误，也没有附上上一响应，小模型难以针对性纠正。

**现在的处理链**：

```text
合法示例 + 明确字段/状态规则
    ↓
json_schema：必填字段、枚举、数组、数值范围、禁止额外字段
    ↓ 端点明确拒绝格式才降级
json_object → 文本 JSON
    ↓
Zod 严格校验 + 原文/ID/片段核对 + 单句/篇章规则
    ↓ 失败时最多修复一次
上一响应 + 具体字段路径和中文原因 → 重新生成完整 JSON
    ↓
通过则显示；仍失败则展示具体错误及重试入口
```

不把字符串 confidence 自动转换为数字，不自行填补缺失的中文说明，不猜测原文，不静默接受非法枚举。格式约束降低错误概率，最终校验仍是必需的；不能保证所有模型的每次响应都成功。

兼容格式最多降级两次，瞬态网络/限流重试最多两次，语义格式修复最多一次，总共最多 6 次 HTTP 尝试。每次尝试分别计时。错误诊断只回显已知字段名及固定描述，不显示原始服务端错误正文、凭据或未知字段值。

**代码**：[response-schema.ts](../electron/llm/response-schema.ts)、[provider.ts](../electron/llm/provider.ts)、[schema.ts](../src/models/schema.ts)。

协议依据：[Ollama 官方结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)明确支持在 OpenAI-compatible API 中通过 `response_format` 提供结构约束。

## 4. 连续请求、排队与超时

**旧行为**：主进程全局最多并发 2 条请求。因此第一句分析时，第二句可能已发送到 Ollama。超时原本就在每次 HTTP 请求前开始，应用主进程队列中的等待并不计时；但 Ollama 内部的等待、加载和生成均已属于 HTTP 请求耗时。此外 UI 在请求刚提交 IPC 时就显示“分析中”，无法区分实际排队。

**现在的行为**：

- 同一 Ollama 服务按协议、主机和端口分组，每组串行执行；同一服务下的多个模型配置共享限制，localhost 与回环地址归为同组。
- 全局并发上限仍为 2，不同服务可以并行；后续本地句子在应用队列中等待，不占用请求超时。
- 主进程发送 `llm:progress` 事件，以请求 UUID 标识 queued/running。卡片分别显示“排队中”和“分析中”，全文分析使用相同机制。
- 第一句执行期间，后续句子仍可完成分句并进入队列，编辑器不等待模型。
- 超时仍覆盖 HTTP 发出后的连接、模型加载、服务端内部等待与生成。本应用无法消除其他客户端对同一 Ollama 产生的资源竞争，也没有擅自延长用户设置。

**代码**：[queue.ts](../electron/llm/queue.ts)、[provider.ts](../electron/llm/provider.ts)、[Electron main.ts](../electron/main.ts)、[preload.ts](../electron/preload.ts)、[coordinator.ts](../src/core/coordinator.ts)、[FeedbackCard.tsx](../src/components/FeedbackCard.tsx)。

## 5. 真实模型验证

使用用户已经配置的本机 `gemma3:12b`，保持每次请求 **30,000 ms** 超时。没有启动/下载模型，没有发送实际作文，没有读取凭据文件。四个固定句子同时进入应用队列：

| 固定句子 | 返回状态 | 应用排队 | 本次调用耗时 | HTTP 次数 |
| --- | --- | ---: | ---: | ---: |
| Learning takes practice. | good | 0.000 秒 | 12.779 秒 | 1 |
| He go to school every day. | needs_revision | 12.779 秒 | 11.106 秒 | 1 |
| I think online courses are quite efficiency and convenience. | needs_revision | 23.885 秒 | 15.568 秒 | 1 |
| Students can review difficult material whenever they need to. | good | 39.455 秒 | 4.989 秒 | 1 |

全部通过结构、中文、原文和修改建议校验，未触发降级或修复。总计约 44.450 秒，同时运行的请求峰值为 1。第 4 句排队超过 30 秒仍正常完成，直接验证了排队不消耗单次请求超时。以上是本次运行测量，不是速度或语法判断准确率承诺。

可复验命令：

```bash
npm run test:ollama
```

[脚本](../scripts/ollama-smoke.mjs)默认读取 macOS 应用设置文件，仅允许无需认证的本机回环 Ollama 地址。可通过 `TWA_OLLAMA_SETTINGS` 指定另一份设置 JSON。检查只读取设置并使用固定测试句，不修改用户数据。
